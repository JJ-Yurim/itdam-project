# 잇담 포팅 매뉴얼

GitLab 소스 클론 이후 빌드·배포에 필요한 모든 정보를 담는다. 저장소는 모노레포이며
`backend/`(Spring Boot), `ai-service/`(FastAPI), `frontend/`(React), `infra/`(Compose)로 구성된다.

## 1. 사용 제품과 버전

### 1.1 런타임·프레임워크

| 구분 | 제품 | 버전 | 비고 |

## 2. 빌드 방법과 환경 변수

### 2.1 로컬 인프라 기동 (공통 선행)

```powershell
Copy-Item infra/.env.example infra/.env   # 비밀번호를 채운다
docker compose --env-file infra/.env -f infra/compose.yml up -d
```

`infra/.env`에서 요구하는 변수: `POSTGRES_DB` `POSTGRES_USER` `POSTGRES_PASSWORD`
`REDIS_PASSWORD` `RABBITMQ_USER` `RABBITMQ_PASSWORD` `RABBITMQ_VHOST` (포트 재정의는 선택).

### 2.2 백엔드

```powershell
cd backend
.\gradlew.bat test                                            # H2 기반, Docker 불필요
.\gradlew.bat bootRun --args='--spring.profiles.active=local' # 로컬 실행
.\gradlew.bat bootJar                                         # build/libs/app.jar
```

- Flyway가 기동 시 `db/migration/V1~V16`을 적용하고 Hibernate는 `validate`만 수행한다.
- Testcontainers 통합 테스트: `.\gradlew.bat infraTest` (Docker 필요).
  Spring↔FastAPI HTTP 계약 검증은 계약 이미지가 필요하다:

```powershell
docker build -t c206-ai-contract-test:local -f ai-service/Dockerfile.test ai-service
$env:AI_CONTRACT_TEST_IMAGE = 'c206-ai-contract-test:local'
.\gradlew.bat infraTest
```

**백엔드 런타임 환경 변수** (배포 시 Jenkins가 주입, 로컬은 대부분 기본값으로 동작):

## 3. 배포 방법과 특이사항

### 3.1 배포 구조

```
인터넷 → EC2 호스트 nginx (443, TLS)
  ├─ /            → frontend-app 컨테이너 (루프백 포트)
  ├─ /api/        → upstream c206_backend { 127.0.0.1:8081, 8082 }  ← 백엔드 이중 인스턴스
  ├─ /images/     → /var/www/images (보스·표지 이미지, 호스트 볼륨)
  ├─ /ops/logs/   → Grafana (Basic Auth)
  └─ /api/swagger-ui/ 등 문서 경로 → Basic Auth 추가 보호
모든 앱 컨테이너는 Docker 네트워크 `mvp-infra`에서 postgres/redis/rabbitmq 서비스 DNS로 접속
```

- develop 브랜치 머지 → Jenkins가 변경 영역만 감지(changeset)해 해당 파이프라인만 실행.
- 백엔드는 **A/B 슬롯 이중 인스턴스**(`backend-app-a`:8081, `backend-app-b`:8082)로 순차
  교체 배포된다. 세션은 Redis(spring-session)로 공유되고, 스케줄러(평가 릴레이·회수·책 회수·
  이미지 정리)는 **ShedLock**(Redis 잠금)으로 한 인스턴스만 실행된다.
  상세: [`배포-런북/백엔드-이중-인스턴스.md`](배포-런북/백엔드-이중-인스턴스.md)
- 프론트·AI 서비스는 단일 컨테이너 교체 배포이며, 헬스체크 실패 시 스크립트가 이전
  이미지로 롤백한다 (`scripts/deploy-*.sh`).

### 3.2 배포 시 특이사항 (순서 의존·주의점)

1. **Flyway는 롤백되지 않는다.** 새 마이그레이션이 적용된 뒤 이전 백엔드 이미지로 되돌리면
   Flyway validation이 실패한다. 마이그레이션이 포함된 배포의 롤백은 이미지가 아니라
   후속 수정 배포로 처리한다.
2. **pgvector 이미지 필수.** 공식 `postgres` 이미지에는 vector 확장이 없어 V4가 실패한다.
   기존 alpine 볼륨에서 전환할 때의 collation 확인 절차는 `infra/README.md` 참조.
3. **ai-service readonly 계정 비밀번호 회전 순서**: Jenkins 자격증명
   (`develop-ai-readonly-db-password`) 변경 → **백엔드 먼저 재배포**(마이그레이션이
   `ALTER ROLE` 수행) → ai-service 재배포. 순서를 바꾸면 ai-service 인증이 실패한다.
4. **어댑터 스위치 기본값은 안전한 쪽**이다. 코드 기본은 `sync`/`logging`/`fake`이고 배포
   프로필·env가 `rabbit`/`http`/`pgvector`로 켠다. 스위치가 하나만 켜져도 시스템은 안전하다
   (예: 백엔드만 rabbit이면 15분 stale 회수가 실패 처리·평가권 반환).
5. **관측 스택은 별도 파이프라인**(`Jenkinsfile.observability`)이다. 로그 스택 장애가
   애플리케이션 배포·롤백을 막지 않는다.
6. **이미지 파일은 DB가 아니라 호스트 볼륨**(`/var/www/images`)에 있다. DB 덤프만으로는
   보스 이미지가 복원되지 않으므로 서버 이전 시 이 디렉터리를 함께 복사한다.
7. Swagger·Grafana 등 문서·운영 경로는 nginx **Basic Auth** 뒤에 있다
   (`/etc/nginx/.htpasswd-api-docs`, `.htpasswd-ops-log`).
8. Jenkins 파이프라인 Job 구성: Pipeline script from SCM, 브랜치 `*/develop`,
   Script Path에 각 Jenkinsfile 지정. 필요한 자격증명 목록은
   [`배포-런북/Jenkins-자격증명과-배포-절차.md`](배포-런북/Jenkins-자격증명과-배포-절차.md) 참조.

## 4. DB 접속 정보와 프로퍼티 정의 파일 목록

### 4.1 접속 정보

DB 이름은 `mvp_backend`이며, 애플리케이션 컨테이너는 Docker 네트워크 `mvp-infra`의 서비스
DNS로 접속한다. 호스트에서 직접 붙을 때는 `localhost`를 쓴다.

| 서비스 | 컨테이너 기준 | 호스트 기준 | 계정 출처 |
| --- | --- | --- | --- |
| PostgreSQL | `postgres:5432` | `localhost:5432` | `POSTGRES_USER` / `POSTGRES_PASSWORD` |
| Redis | `redis:6379` | `localhost:6379` | `REDIS_PASSWORD` (계정 없음) |
| RabbitMQ | `rabbitmq:5672` (관리 UI 15672) | `localhost:5672` | `RABBITMQ_USER` / `RABBITMQ_PASSWORD`, vhost `/` |

### 4.2 DB 계정

| 계정 | 권한 | 사용처 | 비밀번호 출처 |
| --- | --- | --- | --- |
| `c206` | 소유자 (DDL·DML) | 백엔드 Flyway·JPA | `infra/.env` / Jenkins `develop-postgres` |
| `mvp_ai_readonly` | `SELECT` 전용 | ai-service 책 재료 조회. `V7` 마이그레이션이 생성하며 쓰기는 DB가 거부 | Jenkins `develop-ai-readonly-db-password` |

스키마의 단일 출처는 Flyway `backend/src/main/resources/db/migration/`(V1~V16)이고, ERD는
`docs/implementation/itdam-erd.dbml`이다. 개인정보가 포함된 운영 DB 덤프는 공개 저장소에서 제외한다.
비밀값은 저장소에 없으며 Jenkins 자격증명과 서버의 `infra/.env`에만 존재한다.
